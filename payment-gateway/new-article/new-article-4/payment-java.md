Этот класс представляет собой сущность для хранения информации о платеже. Он используется для описания платёжных данных, таких как ID заказа, сумма платежа, захваченная сумма и статус платежа.

#### \#Пакет:

```
package com.example.payment.gateway.domain;
```

#### \#Импорты:

```
import jakarta.persistence.*;
import lombok.*;
```

#### \#Аннотации:

-  `@Entity`: Означает, что класс является сущностью JPA и будет маппирован в таблицу базы данных.

-  `@Getter`, `@Setter`: Генерирует геттеры и сеттеры для всех полей класса.

-  `@NoArgsConstructor`: Генерирует конструктор без параметров.

-  `@Version`: Означает, что это поле будет использоваться для контроля версий (Optimistic Locking) и предотвращения конфликтов при одновременной записи.

---

### \#Поля:

1. **id**:

   ```
   @Id
   @GeneratedValue(strategy = GenerationType.IDENTITY)
   private Long id;
   ```

   Это уникальный идентификатор платежа, который генерируется автоматически при сохранении записи в базе данных.

2. **orderId**:

   ```
   private Long orderId;
   ```

   Идентификатор заказа, с которым связан этот платёж.

3. **amount**:

   ```
   private Long amount;
   ```

   Сумма, которую пользователь заплатил.

4. **capturedAmount**:

   ```
   private Long capturedAmount;
   ```

   Сумма, которая была захвачена из общего платёжного объёма (например, при частичном захвате).

5. **status**:

   ```
   @Enumerated(EnumType.STRING)
   private PaymentStatus status = PaymentStatus.INIT;
   ```

   Статус платежа. Используется перечисление `PaymentStatus`, которое хранит состояние платежа, например, `INIT` (инициализирован), `COMPLETED` (завершён), `FAILED` (неудачный) и другие. Статус по умолчанию устанавливается в `INIT`.

6. **version**:

   ```
   @Version
   private Integer version;
   ```

   Поле для поддержки контроля версий (Optimistic Locking), которое используется для предотвращения конфликтов при параллельных изменениях данных.

---

### \#Резюме:

Класс `Payment` представляет собой сущность для хранения информации о платеже, включая ID заказа, сумму, захваченную сумму и статус. Статус платежа хранится как перечисление `PaymentStatus`, а для контроля параллельных изменений используется механизм оптимистичной блокировки с помощью поля `version`.
